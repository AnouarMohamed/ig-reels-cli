Failure Modes Table

| Failure Scenario                          | Component Detecting It          | System Response                                                                 | User Sees / Impact                                                                 |
|-------------------------------------------|---------------------------------|---------------------------------------------------------------------------------|-----------------------------------------------------------------------------------|
| Instagram challenge/checkpoint triggered  | ig_client.py (login_or_login)   | - load_or_login raises ChallengeRequired/CheckpointRequired.<br>- daemon.py catches and returns {"error":"challenge_required", "detail":...}.<br>- Daemon continues listening; does not crash. | On first `get_reels` after login attempt, client receives error.<br>User must manually solve challenge via Instagram app/website, then delete session.json (or let daemon create new) and retry login. |
| Socket connection dropped (client side)   | Rust ipc.rs (UDS client)        | - recv returns None or error.<br>- ipc.rs propagates error to fetch.rs/app.rs.<br>- App may retry connection after backoff or show error. | If occurs during batch fetch, next reel may stall; user sees frozen UI or error message in status line. Manual restart of Rust app may be needed. |
| Socket connection dropped (daemon side)   | daemon.py (accept loop)         | - Exception in recv/send caught, logged.<br>- Connection closed; daemon waits for next client. | No direct user impact if Rust app reconnects; if not, Rust app will see connection error as above. |
| FFmpeg decode failure (missing/invalid MP4) | decode.rs (ffmpeg-next)         | - VideoDecoder returns error or EOF prematurely.<br>- decode.rs propagates error via channel.<br>- app.rs logs and skips to next reel (or shows error). | Playback stops abruptly; user may see blank screen or error in status line, then auto-advance to next reel if available. |
| FFmpeg audio extraction failure           | audio.rs (ffmpeg-next)          | - AudioDecoder returns error.<br>- audio.rs logs; may continue with silent audio or skip audio. | Video plays without audio; user notices missing sound. |
| Instagram rate limit hit (429/403)        | ig_client.py (get_reels_batch)  | - instagrapi raises exception (likely HTTPError).<br>- ig_client.py propagates; daemon.py catches and returns {"error":"internal_error","detail":...}. | Client receives error response; user sees error in status line or console. May need to wait before retrying. |
| Terminal resize mid‑playback              | Crossterm (input.rs or render.rs) | - crossterm reports Resize event.<br>- input.rs forwards to app.rs.<br>- app.rs updates terminal dimensions and notifies render.rs to recompute layout (e.g., frame scaling). | Video frame dimensions adjust smoothly; no interruption. If not handled, video may appear stretched or cropped until next redraw. |
| Out of disk space (tmp-cache full)        | download.rs (file write)        | - Write returns error.<br>- download.rs aborts download, returns error to fetch.rs.<br>- app.rs logs and may skip reel or show error. | Download fails; if reel not available, playback skips to next available reel or shows error. |
| Corrupted MP4 file (partial download)     | decode.rs / audio.rs            | - FFmpeg fails to open stream or returns garbled frames.<br>- Treated as decode failure (see above). | Similar to decode failure: playback error, skip to next reel. |
| daemon.py crash (uncaught exception)      | daemon.py (top‑level)           | - Process exits; UDS socket file removed on SIGTERM? Not guaranteed.<br>- Rust client sees connection dropped. | Rust app shows connection error; user must restart daemon manually (or supervisor restarts it). |
| Missing environment variables (username/password) | daemon.py (startup)           | - Prints error and exits.<br>- Socket not created. | User sees error on daemon start; must set INSTAGRAM_USERNAME/PASSWORD in .env or environment. |
